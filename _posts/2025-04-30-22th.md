# FastAPI + MongoDB: ObjectId를 문자열로 바꾸는 이유와 변환 함수 만들기

FastAPI에서 MongoDB와 연동해 데이터를 조회하거나 응답으로 반환할 때, 가장 자주 마주치는 문제 중 하나는 바로 **`ObjectId` 타입의 직렬화 오류**입니다.

```bash
TypeError: Object of type ObjectId is not JSON serializable
```

왜 이런 문제가 발생할까요? 그리고 어떻게 해결할 수 있을까요? 이번 글에서는 그 원인을 짚고, 이를 해결하기 위한 **`convert_objectid()` 재귀 함수**의 구현과 사용 방법을 소개합니다.

---

## 🔍 왜 ObjectId는 JSON으로 바로 반환할 수 없을까?

MongoDB의 기본 키인 `_id` 필드는 `ObjectId`라는 BSON(Binary JSON) 타입으로 저장됩니다. 이 타입은 MongoDB 내부적으로는 매우 효율적이지만, Python의 기본 JSON 모듈이나 FastAPI의 `JSONResponse`에서는 인식하지 못합니다.

즉, 다음과 같은 코드에서 오류가 발생합니다:

```python
from fastapi import FastAPI
from pymongo import MongoClient

app = FastAPI()
client = MongoClient()
collection = client.db.collection

@app.get("/item")
def get_item():
    doc = collection.find_one()
    return {"data": doc}  # TypeError 발생!
```

---

## 🛠 해결책: ObjectId를 문자열로 바꿔주자

이를 해결하기 위해, MongoDB에서 가져온 데이터를 Python에서 직렬화 가능한 형태로 바꿔줘야 합니다. 그중 가장 흔한 방법은 **ObjectId를 문자열로 변환**하는 것입니다.

---

## ✅ 재귀적으로 ObjectId를 변환하는 함수

단일 문서뿐 아니라 리스트로 여러 문서를 조회했을 때도 모두 변환할 수 있도록 **재귀적인 변환 함수**를 정의합니다:

```python
def convert_objectid(data):
    if isinstance(data, list):
        return [convert_objectid(item) for item in data]

    if isinstance(data, dict):
        return {
            key: str(value) if key == '_id' else convert_objectid(value)
            for key, value in data.items()
        }

    return data
```

### 이 함수의 핵심 기능:

- `list` 안의 각 요소들을 재귀적으로 탐색
- `dict` 안의 `_id` 키가 있으면 `str()`로 변환
- 다른 데이터 타입은 그대로 반환

---

## 🎯 사용 예시

```python
doc = {
    "_id": ObjectId("6617ae3341e8b339c8a2a1a1"),
    "날짜": "2025.04.28",
    "정보": {
        "_id": ObjectId("6617ae3341e8b339c8a2a1a2"),
        "작성자": "홍길동"
    }
}

converted_doc = convert_objectid(doc)

# 결과:
# {
#     "_id": "6617ae3341e8b339c8a2a1a1",
#     "날짜": "2025.04.28",
#     "정보": {
#         "_id": "6617ae3341e8b339c8a2a1a2",
#         "작성자": "홍길동"
#     }
# }
```

이제 이 `converted_doc`을 FastAPI의 응답으로 안전하게 리턴할 수 있습니다:

```python
from fastapi.responses import JSONResponse

@app.get("/item")
def get_item():
    doc = collection.find_one()
    return JSONResponse(content=convert_objectid(doc))
```

---

## 🔚 마무리

MongoDB의 `ObjectId`는 매우 강력한 고유 식별자이지만, JSON으로 직접 반환할 수 없는 점 때문에 번거로운 작업이 필요합니다. `convert_objectid()` 함수를 통해 이 문제를 간단히 해결하고, 리스트든 중첩된 문서든 모두 안전하게 직렬화할 수 있습니다.

# 🧑‍💻 FastAPI + MongoDB: `response_model`을 왜 모델로 변환해야 할까?

FastAPI를 사용하면서 MongoDB와 연결하여 학생 정보를 가져오는 간단한 API를 만들다가 아래와 같은 고민이 들었습니다:

> _"MongoDB에서 바로 데이터를 가져오는데, 굳이 Pydantic 모델로 변환해야 해? 그냥 딕셔너리 리스트 반환하면 안 돼?"_

이 글에서는 그 이유를 코드와 함께 명확히 정리해봅니다.

---

## 🏗 기본 코드 구조

```python
from fastapi import FastAPI
from pydantic import BaseModel
from pymongo import MongoClient

app = FastAPI()
client = MongoClient("mongodb://localhost:27017")
db = client["school"]
collection = db["students"]

class StudentOut(BaseModel):
    name: str
    age: int
    student_id: str
    class_name: str
    subject: str
```

`StudentOut`은 우리가 클라이언트에게 응답으로 내려주고 싶은 학생 정보를 정의한 모델입니다.

---

## ❓ 첫 번째 시도: MongoDB 쿼리 결과를 그대로 반환

```python
@app.get("/students/subject/", response_model=list[StudentOut])
def get_class(subject: str):
    students = list(collection.find({"subject": subject}))
    return students
```

이렇게 작성하면 오류가 발생할 수 있습니다. 이유는 간단합니다:

- `collection.find()`의 결과는 \*\*MongoDB 문서(Dict)\*\*입니다.
- 문서에는 `"_id"` 필드도 포함되어 있고, `Pydantic`이 정의한 필드 외의 데이터도 포함됩니다.
- 따라서 `FastAPI`는 `response_model`에 맞는 응답을 직렬화하려다 실패합니다.

---

## ✅ 해결 방법: `StudentOut` 모델로 변환

```python
@app.get("/students/subject/", response_model=list[StudentOut])
def get_class(subject: str):
    cursor = collection.find({"subject": subject})
    students = [
        StudentOut(
            name=doc["name"],
            age=doc["age"],
            student_id=doc["student_id"],
            class_name=doc["class_name"],
            subject=doc["subject"]
        )
        for doc in cursor
    ]
    return students
```

여기서 핵심은 **Pydantic 모델로 명시적으로 감싸주는 것**입니다.

### 이유:

1. **MongoDB 문서는 딕셔너리**이며, FastAPI는 이를 자동으로 `StudentOut`으로 인식하지 못합니다.
2. `response_model`을 지정하면 FastAPI는 내부적으로 **직렬화 및 검증**을 시도하는데, dict가 모델 형식이 아니면 실패합니다.
3. `Pydantic` 모델은 필드 정의, 타입 체크, 직렬화를 도와줍니다.

---

## ✏️ 간단한 요약

| 구분                              | 설명                                     |
| --------------------------------- | ---------------------------------------- |
| `collection.find()`               | MongoDB 문서를 dict로 반환               |
| `response_model=list[StudentOut]` | 응답이 `StudentOut` 리스트 형식이길 기대 |
| 해결 방법                         | 각 dict → `StudentOut` 객체로 변환 필요  |

---

## 🧠 교훈

FastAPI에서 `response_model`을 지정한 경우, 응답 데이터는 **반드시 해당 모델의 인스턴스이거나 그에 맞는 구조**여야 합니다. MongoDB에서 받은 raw 데이터는 그대로 쓰면 에러가 발생할 수 있으므로, **명시적으로 Pydantic 모델로 감싸는 과정이 꼭 필요**합니다.

이러한 변환 과정은 번거로워 보일 수 있지만, 오히려 덕분에 데이터 구조에 대한 신뢰성과 타입 안정성이 확보됩니다.

---

### ✍️ 마무리

FastAPI는 매우 강력한 타입 시스템과 검증 기능을 제공합니다. MongoDB 같은 NoSQL 데이터베이스와 연동할 때는 이러한 타입 시스템을 활용하여 **더 안정적이고 명확한 API 응답 구조**를 만드는 것이 좋습니다.

> 결국, “왜 모델로 변환해야 하냐”는 질문에 대한 답은 이렇습니다: **FastAPI가 제대로 작동하기 위해서고, 우리가 실수하지 않도록 돕기 위해서입니다.**

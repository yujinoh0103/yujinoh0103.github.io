# 📌 FastAPI 개발자가 한 번쯤은 궁금해할 CORS, origins, host 설정 개념 총정리

FastAPI로 프로젝트를 개발하다 보면 다음과 같은 질문이 떠오릅니다.

- `origins`는 왜 설정하는 걸까?
- `host="0.0.0.0"`은 어떤 의미지?
- CORS는 도대체 어디서, 왜 설정하는 건가?
- 고정 IP를 받으면 뭐가 좋아지는 거지?
- 로컬 개발 중 핸드폰에서도 접근되는데, origins에 localhost만 넣어도 되나?

이 포스팅은 이런 의문들을 하나하나 풀어가는 과정에서 얻은 개념들을 정리한 글입니다.

---

## 🧠 CORS란 무엇인가?

\*\*CORS (Cross-Origin Resource Sharing)\*\*는 말 그대로 "다른 출처의 요청을 공유할 수 있는지"에 대한 브라우저의 보안 정책입니다.
브라우저는 보안을 위해 \*\*출처(origin)\*\*가 다른 곳에서 요청이 오면 이를 **차단**합니다.

> 출처(origin)란 `프로토콜 + 도메인 + 포트번호`를 의미합니다.
> 예: `http://localhost:3000`과 `http://127.0.0.1:3000`은 서로 다른 origin입니다.

---

## 🛡️ FastAPI에서 CORS 설정 방법

FastAPI에서는 `CORSMiddleware`를 이용해 CORS 정책을 설정합니다.

```python
from fastapi.middleware.cors import CORSMiddleware

app.add_middleware(
    CORSMiddleware,
    allow_origins=["http://localhost:3000"],  # 허용할 프론트 주소
    allow_credentials=True,
    allow_methods=["*"],
    allow_headers=["*"],
)
```

이 설정을 하지 않으면, 프론트엔드에서 백엔드로 API 요청을 보낼 때 브라우저에서 CORS 오류가 발생할 수 있습니다.

---

## 🌐 origins는 무슨 의미일까?

`allow_origins`는 \*\*"어떤 도메인에서 오는 요청을 허용할지"\*\*에 대한 설정입니다.

예를 들어,

- 내가 만든 백엔드는 `http://192.168.0.10:8000`에서 열려 있고,
- 프론트는 `http://localhost:3000`에서 실행되고 있다면,

`allow_origins`에 `http://localhost:3000`을 포함시켜야 브라우저가 API 요청을 허용합니다.

---

## ⚙️ host="0.0.0.0"은 뭔가요?

FastAPI를 실행할 때 다음과 같은 명령어를 쓰곤 하죠.

```bash
uvicorn main:app --host 0.0.0.0 --port 8000
```

여기서 `host="0.0.0.0"`은 \*\*"모든 네트워크 인터페이스에서 접근 허용"\*\*을 의미합니다.
즉, **같은 네트워크에 있는 다른 디바이스**에서도 서버에 접근할 수 있게 해줍니다.

> `127.0.0.1` 또는 `localhost`는 오직 \*\*자기 자신(내 컴퓨터)\*\*만 접근 가능하게 합니다.

---

## 📱 핸드폰에서 FastAPI 접속이 가능한 이유?

만약 FastAPI를 `host="0.0.0.0"`으로 실행하고 있고,
핸드폰이 **같은 와이파이 네트워크에 연결**되어 있다면,

`http://<내컴퓨터-로컬IP>:8000`으로 핸드폰에서 접근이 가능합니다.

이때 `origins=["http://localhost:3000"]`이라고 설정해도 핸드폰에서는 접근이 됩니다.
왜냐하면 **CORS는 브라우저 보안 정책**이고, 단순히 주소에 접근하는 건 막지 않기 때문입니다.

---

## 🧩 host 설정과 origins 설정은 왜 따로 하는가?

이 둘은 완전히 다른 역할입니다.

| 항목            | 의미                                                          | 적용 대상       |
| --------------- | ------------------------------------------------------------- | --------------- |
| `host`          | 서버가 **어떤 네트워크 인터페이스에서 요청을 받을지** 설정    | 백엔드 서버     |
| `allow_origins` | **어떤 프론트/도메인에서 온 요청을 브라우저가 허용할지** 설정 | 브라우저 (CORS) |

---

## 📌 고정 IP를 받는 이유는?

- IP 주소가 고정되어야 **외부에서 내 서버에 안정적으로 접근**할 수 있습니다.
- 하지만 고정 IP가 있다고 해도, 접속자는 각자 다른 IP를 가지고 있기 때문에 CORS 설정은 여전히 필요할 수 있습니다.
- 즉, **고정 IP는 주소의 변동 없음**, **CORS는 요청을 허용할지 말지 결정** — 서로 다른 목적입니다.

---

## ✅ 정리

- CORS는 브라우저의 보안 정책
- `allow_origins`는 허용할 출처(origin)를 명시
- `host="0.0.0.0"`은 외부 접속을 열기 위한 설정
- 핸드폰이나 다른 기기에서 접근하려면 같은 네트워크 + 0.0.0.0 설정 필요
- 고정 IP를 쓰면 외부 접근은 편해지지만, 여전히 CORS 정책은 신경 써야 함

# 💻 EC2 Instance Connect 접속 오류 해결 가이드 (SSH 안 될 때 확인할 것들)

Amazon EC2 인스턴스를 Instance Connect로 접속하려고 할 때, 아래와 같은 오류를 만나는 경우가 있습니다

> ❌ **"There was a problem connecting to your instance"**

이럴 땐 당황하지 말고, 아래 체크리스트를 하나씩 따라가면 대부분의 문제가 해결됩니다.

---

## ✅ 1. 보안 그룹 설정 확인

먼저 **보안 그룹에서 포트 22(SSH)**가 열려 있는지 확인하세요.

- **인바운드 규칙**에 아래와 같은 항목이 있어야 합니다:

| Type | Protocol | Port | Source                            |
| ---- | -------- | ---- | --------------------------------- |
| SSH  | TCP      | 22   | `0.0.0.0/0` 또는 접속하려는 내 IP |

### 🔍 확인 경로:

1. EC2 대시보드 → 인스턴스 선택
2. 아래 `보안` 탭 → 연결된 보안 그룹 클릭
3. `인바운드 규칙` 탭에서 확인 및 수정

---

## ✅ 2. 퍼블릭 IP가 할당되어 있는지 확인

EC2 Instance Connect는 **퍼블릭 IP**가 있는 인스턴스에서만 정상 동작합니다.

- 인스턴스 세부 정보에 **IPv4 Public IP**가 있는지 확인
- 없다면:
  - EC2 인스턴스 종료 후 **퍼블릭 IP 자동 할당 활성화**하여 다시 시작하거나,
  - **탄력적 IP(Elastic IP)**를 할당

---

## ✅ 3. 라우팅 테이블 확인 (인터넷 게이트웨이 연결 여부)

퍼블릭 서브넷에 있는 인스턴스라면, 라우팅 테이블에 **인터넷 게이트웨이(IGW)**가 연결돼 있어야 합니다.

### 라우팅 테이블에 다음 항목이 있어야 함:

```
Destination: 0.0.0.0/0 → Target: igw-xxxxxxxx
```

> VPC → 서브넷 → 라우팅 테이블 → 라우팅 확인

---

## ✅ 4. 지원되는 OS 이미지인지 확인

- EC2 Instance Connect는 **Amazon Linux 2**, **Ubuntu 20.04 이상** 등에서 지원됩니다.
- 커스텀 AMI나 OpenSSH 미설치 상태에서는 작동하지 않을 수 있습니다.

---

## ✅ 5. SSH 키 관련 설정이 막혀 있는지 확인

Instance Connect는 **IAM 기반으로 임시 SSH 키를 삽입**해서 접속합니다.

→ 만약 아래 중 하나라도 해당된다면 오류가 날 수 있습니다:

- `cloud-init` 설정이 SSH 키 삽입을 막고 있는 경우
- `sshd_config`에서 `AuthorizedKeysCommand` 등이 변경된 경우

---

## ✅ 6. IAM Role 및 정책 확인

EC2 Instance Connect 사용을 위해서는 IAM 권한이 필요합니다.

### 필요한 정책 예시:

```json
{
  "Effect": "Allow",
  "Action": ["ec2-instance-connect:SendSSHPublicKey"],
  "Resource": "*"
}
```

- IAM 사용자나 인스턴스 프로파일에 이 권한이 포함되어 있어야 합니다.

---

## 🧪 추가 팁: SSH 직접 접속으로 우회하기

EC2 Instance Connect가 안 되는 상황에서는 **직접 SSH로 접속하는 것도 가능**합니다.

```bash
ssh -i /path/to/your-key.pem ec2-user@your-ec2-public-ip
```

- `ec2-user`는 Amazon Linux 기준
- Ubuntu일 경우 `ubuntu` 사용자 사용

🔒 이때도 포트 22가 열려 있어야 하고, `.pem` 키 권한은 `chmod 400`으로 제한해야 합니다.

# 사이킷런의 **파이프라인(Pipeline)** 기능

모델 학습까지 일련의 작업을 **순서대로 묶어서 자동화**해 주는 도구입니다. 특히 **전처리 과정과 모델을 함께 묶어 학습하고 예측하는 데 매우 유용**하며, 코드의 구조화와 재사용성을 높여줍니다.

---

## 🔧 1. 기본 구조

```python
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression

pipeline = Pipeline([
    ('scaler', StandardScaler()),          # 1단계: 스케일링
    ('classifier', LogisticRegression())   # 2단계: 모델 학습
])
```

- 각 단계는 `(이름, 객체)` 튜플로 구성
- 순서대로 `.fit()`, `.transform()`, `.predict()`가 호출됨

---

## ✅ 2. 사용법 예시

```python
pipeline.fit(X_train, y_train)             # fit: scaler와 모델 모두 학습
y_pred = pipeline.predict(X_test)          # predict: 스케일링 후 예측
```

위 코드는 내부적으로 다음 순서로 동작합니다:

1. `StandardScaler().fit(X_train)` → 평균, 표준편차 계산
2. `X_train`을 변환 (`transform`)
3. 변환된 데이터를 `LogisticRegression().fit(...)`에 전달
4. 이후 `X_test`에도 동일한 스케일링 적용 후 예측

---

## ✅ 3. GridSearch와 함께 사용

파이프라인을 쓰면 **하이퍼파라미터 튜닝도 한 번에** 할 수 있습니다:

```python
from sklearn.model_selection import GridSearchCV

param_grid = {
    'classifier__C': [0.1, 1, 10]  # 모델 내부 파라미터에 접근할 때는 '__' 사용
}

grid = GridSearchCV(pipeline, param_grid, cv=5)
grid.fit(X_train, y_train)
```

---

## 🧠 장점 요약

| 기능               | 설명                                                               |
| ------------------ | ------------------------------------------------------------------ |
| 일관된 처리        | `fit`, `transform`, `predict`를 일관되게 처리                      |
| 코드 간결화        | 전처리와 모델을 하나로 묶어 사용 가능                              |
| 재사용성           | 테스트/추론 시에도 동일한 처리 반복 가능                           |
| 파라미터 튜닝 통합 | `GridSearchCV`, `RandomizedSearchCV` 등과 통합 용이                |
| 파이프라인 안정성  | 훈련 데이터로만 fit하고 테스트 데이터는 transform만 하게 강제 가능 |

# 신경망 구조에서 은닉층 결정

**데이터의 특성**에 따라 맞출 수 있습니다. 정확히는, **데이터의 차원, 복잡도, 패턴의 비선형성 정도**에 따라 네트워크 구조를 조정하는 것이 일반적입니다.

---

### ✅ 데이터 특성과 은닉층 구조 맞추기

| 데이터 특성                             | 네트워크 구조 조정 예시                    |
| --------------------------------------- | ------------------------------------------ |
| **입력 차원이 낮고 선형적 경향**        | 은닉층 1\~2개, 뉴런 수 적당히              |
| **비선형적이고 복잡한 경향**            | 은닉층 3개 이상, 활성화 함수 적극 사용     |
| **시간적인 연속성(시계열 등)**          | RNN, LSTM 계열 구조                        |
| **공간적 구조(이미지 등)**              | CNN 계열, 필터 구조 활용                   |
| **특징이 희소하거나 고차원(자연어 등)** | 차원 축소 or attention 기반 구조 사용      |
| **데이터 양이 적음**                    | 과적합 방지를 위해 얕은 구조 + 정규화 기법 |
| **데이터 양이 많음**                    | 깊은 구조도 가능 (딥러닝의 장점 발휘)      |

---

### 💡 일반적인 조정 기준

1. **은닉층 수**:

   - 1\~2개로도 대부분의 문제는 해결 가능 (특히 MLP에서)
   - 복잡한 문제일수록 은닉층을 늘리되, 오버피팅에 주의

2. **뉴런 수**:

   - 입력보다 적거나 비슷하게 시작하고, 중간에 확장/축소 가능
   - 너무 많으면 학습 느려지고 오버피팅, 너무 적으면 표현 부족

3. **활성화 함수**:

   - 비선형성 강한 데이터: ReLU, Leaky ReLU, tanh 등 사용
   - 출력 특성 맞춤: 회귀면 Linear, 분류면 Softmax/Sigmoid

---

### 📌 실전 조정 방법

- **Baseline 모델**로 시작 → Validation Loss 기준으로 튜닝
- Grid search, random search, hyperparameter optimization 사용
- 성능과 학습 속도의 trade-off 고려

---

# ReLU가 일부 선형성을 가지는 데도 활성화 함수로 쓰이는 이유

활성화 함수는 비선형성을 부여해서 **신경망이 단순 선형 모델을 넘는 복잡한 함수 근사를 할 수 있게 해주는 핵심 요소**죠. 그런데 ReLU(Rectified Linear Unit)는 다음과 같은 정의를 갖는 함수입니다:

$$
\text{ReLU}(x) = \max(0, x)
$$

즉, 0보다 작으면 0, 0보다 크면 그대로 출력 — 일부 구간에서는 선형이에요. 그런데도 신경망에서는 ReLU가 아주 널리 쓰입니다. 그 이유는 다음과 같아요:

---

### ✅ 1. **비선형성이 존재함**

- ReLU는 입력의 음수 구간에서 출력을 0으로 "꺾어"주기 때문에 전체적으로는 **비선형 함수**입니다.
- 따라서 신경망에 **비선형성을 충분히 부여**할 수 있어요.

---

### ✅ 2. **Gradient Vanishing 문제 완화**

- 시그모이드나 tanh 같은 전통적인 비선형 함수는 입력이 커지면 gradient가 0에 가까워져서 **역전파 시 gradient가 사라지는 문제**(vanishing gradient)가 있었어요.
- ReLU는 양의 영역에서 gradient가 1로 일정해서, **깊은 신경망에서도 gradient가 잘 전달**됩니다.

---

### ✅ 3. **계산이 매우 간단함**

- $\max(0, x)$ 라는 아주 단순한 연산이므로 **계산 비용이 적고 빠름**. 실시간/대용량 학습에서 중요한 요소죠.

---

### ✅ 4. **Sparse activation 유도**

- 음수 입력은 0으로 만들기 때문에, **뉴런의 일부만 활성화되어 sparse한 표현**을 만들어냅니다. 이는 과적합을 줄이거나 연산 효율성 면에서 유리하게 작용할 수 있어요.

---

### 🚧 단점도 있음

- 입력이 0 이하인 경우 gradient가 0이 되어 **그 뉴런은 학습되지 않는 문제**(dead neuron)가 있어요.
- 이를 보완한 것이 **Leaky ReLU**, **ELU**, **GELU** 같은 다양한 변형들이고, 최근에는 \*\*GELU (예: BERT, GPT 계열에서 사용)\*\*가 많이 쓰이기도 합니다.

---

### 🔑 정리하면:

> ReLU는 "전체적으로는 비선형"이고, "계산 효율"과 "gradient 소실 완화"라는 실용적인 장점 덕분에 일부 선형성에도 불구하고 널리 사용됩니다.

# 역전파와 활성화함수

```text
cost를 계산하고 역전파과정에서 경사하강법을 이용해 가중치를 업데이트하는게 lstm 하나에서도 진행이 되잖아
seq2seq같은건 lstm이 여러개 모인 구조를 채택하는데 이런 경우에는 역전파가 레이어의 어디에서 나와?? 그리고 트랜스포머에서 어텐션구조에서는 활성화함수가 왜 없는지도. 옛날 버전 어텐션에는 활성화 함수가 있지 않았는지도 팩트체크하며 알려줘
```

---

## ✅ Q1. **Seq2Seq 구조에서의 역전파는 어디서 시작되나?**

### 🔹 기본 구조 요약:

Seq2Seq는 보통 다음 구조를 가집니다:

```
입력 시퀀스 → [Encoder LSTM] → context 벡터 → [Decoder LSTM] → 출력 시퀀스
```

### 🔹 역전파의 시작 지점:

- **Loss(비용)** 는 decoder의 출력 시퀀스와 실제 정답 시퀀스 간의 차이에서 계산됩니다.
- 따라서 **역전파는 decoder 마지막 시점부터 시작**됩니다.

  - decoder의 LSTM은 여러 time step으로 구성되어 있으므로, time step들을 **역순으로 따라가며** gradient를 흘립니다 (Backprop Through Time, BPTT).
  - decoder를 지나고 나면 **context 벡터 (또는 마지막 encoder hidden state)** 로 gradient가 흘러가고,
  - 다시 encoder 쪽 time step들로 gradient가 전파됩니다.

📌 즉, **Loss는 Decoder 끝에서 나오고 → Decoder LSTM을 거쳐 → Encoder LSTM까지 거꾸로 전달됩니다.**

---

## ✅ Q2. **트랜스포머의 어텐션 구조엔 왜 활성화 함수가 없을까?**

### 🔹 트랜스포머 어텐션 구조 다시 보기:

```text
Self-Attention:
   Q = XW_Q
   K = XW_K
   V = XW_V
   Attention(Q, K, V) = softmax(QKᵀ / √d_k) V
```

- 위에서 보는 것처럼 **어텐션 연산 자체에는 활성화 함수가 없습니다.**
- softmax는 있지만, 이건 출력값을 확률 분포로 바꾸기 위한 것이지 "비선형 활성화"는 아니에요.

### 🔹 이유: **어텐션 자체는 선형 연산의 조합**이기 때문

- 어텐션은 "정보의 가중합"을 수행하는 메커니즘이라, 그 자체에 굳이 활성화 함수를 넣지 않습니다.
- 대신, 트랜스포머는 **어텐션 블록 뒤에 있는 FFN(Feedforward Neural Network)** 부분에서 비선형성을 도입합니다.

### 🔹 트랜스포머에서의 비선형 위치:

```text
LayerNorm
→ Multi-head Attention
→ Add & Norm
→ Position-wise Feedforward Network:
   FFN(x) = max(0, xW₁ + b₁)W₂ + b₂   ← 여기 ReLU 또는 GELU
```

즉, **활성화 함수는 FFN에 포함되며, 어텐션 내부에는 없음**.

---

### 🔹 🔍 팩트체크: 옛날 어텐션(예: Bahdanau, Luong)엔 있었나?

#### ✅ **Bahdanau Attention (2015)**:

```math
score = vᵀ tanh(W₁hₜ + W₂h_s)
```

- 여기서 **tanh가 들어갑니다.**
- 즉, **Bahdanau (Additive) Attention에는 활성화 함수가 사용됨**.

#### ✅ **Luong Attention (2015)**:

- 일반적으로 **dot product**나 **general score** 방식 사용:

```math
score = hₜᵀW h_s  또는  hₜᵀ h_s
```

- 여기는 활성화 함수 **없음**.

✅ **정리하면:**

| 어텐션 종류                | 활성화 함수 유무        |
| -------------------------- | ----------------------- |
| Bahdanau (Additive)        | ✔️ 있음 (tanh)          |
| Luong (Multiplicative)     | ❌ 없음                 |
| Transformer Self-Attention | ❌ 없음                 |
| Transformer FFN            | ✔️ 있음 (ReLU, GELU 등) |

---

## 🔚 요약

- ✅ Seq2Seq의 역전파는 **decoder의 마지막 loss 지점부터** 시작해서 LSTM 구조 전체를 따라 backward됩니다.
- ✅ Transformer에서 어텐션 자체에는 **활성화 함수가 없으며**, 비선형성은 **후속 FFN 블록에서 도입**됩니다.
- ✅ Bahdanau 어텐션은 **tanh 포함**, Luong/Transformer는 **선형 어텐션**입니다.

필요하면 각 어텐션 메커니즘을 수식과 함께 그림으로 시각화해줄 수도 있어요!

# FCN과 FFN이 헷갈림림

## 🔹 1. **FCN (Fully Connected Network)**

### ✅ 의미

- 이름 그대로 **모든 노드가 서로 연결된 네트워크**를 의미해요.
- 흔히 **MLP (Multi-Layer Perceptron)** 과 같은 뜻으로 사용됨.
- 예: 이미지나 벡터 입력을 받아 여러 층의 Dense Layer를 거쳐 출력하는 구조

### ✅ 구조 예시

```text
Input → Linear → ReLU → Linear → ReLU → Output
```

### ✅ 사용 맥락

- 전통적인 분류기 (예: MNIST 분류)
- CNN의 마지막 출력 뒤 fully connected layer
- LSTM 등에서 시퀀스의 마지막 hidden state → FCN → 분류

---

## 🔹 2. **FFN (Feed Forward Network)**

### ✅ 의미

- 일반적인 **순방향 네트워크**를 뜻해요. 순환(recurrent)이나 convolution 없이 단방향으로 신호가 흐름.
- 트랜스포머 구조에서 특히 **"Attention 이후 나오는 작은 MLP 블록"** 을 FFN이라고 부릅니다.

### ✅ Transformer에서 FFN 구조

```text
FFN(x) = max(0, xW₁ + b₁)W₂ + b₂   ← ReLU 또는 GELU 포함
```

- 즉, input vector를 각 위치마다 독립적으로 처리함.
- "포지션별로 독립적인 작은 MLP"라고 보면 됨.

### ✅ 사용 맥락

- Transformer 내부에 반복적으로 등장 (Attention → FFN → LayerNorm)
- Self-Attention이 정보를 모은 후, 각 토큰 위치에서 "비선형 처리"하는 역할

---

## 🔸 정리 표

| 항목        | FCN                           | FFN                                          |
| ----------- | ----------------------------- | -------------------------------------------- |
| 풀네임      | Fully Connected Network       | Feed Forward Network                         |
| 핵심 개념   | 모든 노드 연결된 구조 (Dense) | 순방향 네트워크, 순환 없음                   |
| 사용 위치   | 전통 신경망, CNN 뒤, LSTM 뒤  | Transformer 내부                             |
| 구조 차이   | 일반적인 Dense MLP            | Transformer에서 위치 독립적으로 작동하는 MLP |
| 비선형 함수 | O (ReLU, GELU 등)             | O (ReLU, GELU 등)                            |

---

## 💡 한 줄 정리

> **FFN은 FCN의 특수한 케이스**라고 볼 수 있어요.
> 특히 **Transformer에서는 FFN = 위치별로 독립적인 작은 FCN 블록**이라고 생각하면 딱입니다.

# 🚦 LangGraph 실행 지연 및 모델 호출 에러 디버깅기

## 🧭 배경

LangChain + LangGraph 조합으로 검색 기반 LLM 파이프라인을 구축하던 중, 응답 속도가 너무 느리고 OpenAI 호출에서 에러까지 발생했다. 이번 포스트에서는 다음 두 가지 문제를 해결한 과정을 정리한다.

* LangGraph 실행 속도 병목 문제
* `gpt-3.5-turbo-instruct` 호출 시 발생한 `404 NotFoundError`

---

## 1. LangGraph 실행 지연: 어디서 시간이 걸릴까?

LangGraph 실행 시 다음과 같은 로그가 출력되었다:

```
LangGraph
6.19s
1,285
retrieve_document
0.00s
guardrails
2.09s
plan_retrieval
1.97s
generate_titles
1.93s
ChatOpenAI
gpt-3.5-turbo
1.59s
```

### ⏱ 주요 병목 구간

* `guardrails`: 2.09초
* `plan_retrieval`: 1.97초
* `generate_titles`: 1.93초
* `ChatOpenAI`: 1.59초

### 🔍 원인 분석

LangGraph에서 각 노드는 기본적으로 직렬로 실행된다. 위처럼 각 단계가 비슷한 시간이 걸리고 총합이 6초 이상이라는 것은, 대부분이 **직렬로 처리**되고 있다는 뜻이다.

---

## ✅ 개선 방향

### 1. LangGraph 병렬 실행 구조 확인

`plan_retrieval`, `generate_titles`가 서로 의존하지 않는다면 아래처럼 `add_parallel` 설정으로 병렬화가 가능하다:

```python
graph.add_parallel(["plan_retrieval", "generate_titles"])
```

### 2. Chat 모델 호출 속도 최적화

* `gpt-3.5-turbo`: 기본적으로 빠르지만 `prompt` 길이에 따라 차이 있음
* `temperature=0` 설정 시 속도 안정성 ↑
* 프롬프트 길이를 줄이거나 압축

---

## 2. `gpt-3.5-turbo-instruct` 호출 에러

LangGraph 실행 중 다음과 같은 에러가 발생했다:

```
openai.NotFoundError: 
This is not a chat model and thus not supported in the v1/chat/completions endpoint.
Did you mean to use v1/completions?
```

### 🔎 원인

`gpt-3.5-turbo-instruct`는 **chat 모델이 아니다**. 그런데 LangGraph에서 `ChatOpenAI` 클래스를 사용하고 있어, 강제로 `/v1/chat/completions` 엔드포인트로 요청이 나가면서 404 에러가 발생했다.

---

## 🔧 해결 방법

### 🅰️ 방법 1: 모델에 맞는 LLM 클래스 사용

```python
from langchain.llms import OpenAI
from langchain.prompts import PromptTemplate
from langchain.chains import LLMChain

llm = OpenAI(model="gpt-3.5-turbo-instruct")
prompt = PromptTemplate.from_template("질문: {question}\n오늘 날짜: {today}")
planner_chain = LLMChain(llm=llm, prompt=prompt)
```

> `OpenAI` 클래스는 completion 모델 전용이며, `PromptTemplate`을 함께 사용해야 한다.

---

### 🅱️ 방법 2: chat 모델로 교체 (권장)

LangGraph에서 대부분의 체인은 `ChatOpenAI`와 `ChatPromptTemplate`을 기반으로 동작하므로, chat 모델을 사용하는 게 안전하다.

```python
from langchain.chat_models import ChatOpenAI
from langchain.prompts import ChatPromptTemplate

llm = ChatOpenAI(model="gpt-3.5-turbo")  # 또는 gpt-4o
prompt = ChatPromptTemplate.from_messages([
    ("system", "검색 계획을 수립해 주세요."),
    ("human", "질문: {question}\n오늘 날짜: {today}")
])
planner_chain = LLMChain(llm=llm, prompt=prompt)
```

---

## 📌 정리

| 모델 이름                    | 지원 API                   | 사용할 클래스                  |
| ------------------------ | ------------------------ | ------------------------ |
| `gpt-3.5-turbo`          | ✅ `/v1/chat/completions` | `ChatOpenAI`             |
| `gpt-4` / `gpt-4o`       | ✅ `/v1/chat/completions` | `ChatOpenAI`             |
| `gpt-3.5-turbo-instruct` | ❌ Chat 미지원               | `OpenAI` (completion 전용) |

---

## ✨ 마무리

LangGraph에서 속도가 느리거나, LLM 호출에서 에러가 발생한다면 다음을 점검하자:

* 병렬 실행 설정 (`add_parallel`)
* 사용 모델과 클래스의 조합 (`gpt-3.5-turbo-instruct` vs `ChatOpenAI`)
* 프롬프트 최적화

LangGraph는 powerful하지만, 내부 흐름을 완전히 이해하지 않으면 디버깅이 꽤 어렵다. 이번 문제를 통해 구조를 더 깊게 이해하게 된 계기가 되었다.

```bash
!git config --global user.name "홍길동"
```

## 2. 브랜치 전략

### 2.1 브랜치 구조

- `main`: 배포용 안정 버전 (**작업 금지**)
- `dev`: 모든 기능이 합쳐지는 개발용 브랜치
- `feature/기능이름`: 특정 기능 작업용 (예: `feature/login`)
- `본인 영어이름`: 각자 작업을 할 브랜치. 협업 편의를 위해 브랜치명을 이렇게 지정할게요 (예: `oyj`)

### 2.2 브랜치 생성

```bash
!git checkout -b oyj
```

> `oyj`는 본인의 영어 이니셜이나 이름으로 바꿔주세요.

## 5. Pull Request (PR)

### 5.1 PR이란?

- GitHub에서 브랜치를 `dev`에 병합해달라고 요청하는 것
- 팀 리더 또는 관리자만 merge 가능

### 5.2 PR 작성 방법

- GitHub 저장소 > `Pull Requests` > `New Pull Request`
- base: `dev`, compare: 본인 브랜치 선택
- 작업 내용과 참고사항 작성

### 5.3 코드 리뷰 및 병합

- 리뷰 후 수정 요청이 있을 수 있어요
- 리뷰 통과되면 `dev` 브랜치에 merge합니다

---

## 6. 충돌 해결

- `git pull`로 최신 상태를 받아온 후 충돌 발생 시 수동으로 수정
- 수정 후 커밋하고 다시 push하면 됩니다

---

## 7. 협업 팁

- 커밋 메시지는 prefix 사용 권장: (`feat:`, `fix:`, `docs:` 등)
- `.gitignore` 파일을 꼭 활용해 불필요한 파일은 제외하기 (예: `__pycache__/`, `.ipynb_checkpoints/`)

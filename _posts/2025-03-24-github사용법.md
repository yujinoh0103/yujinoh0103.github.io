## 1. GitHub 설정 및 저장소 클론

1~2번 과정은 지금 작업하고 있는 모델델 파일 말고 다른 파일에서 별도로 진행해주세요.

### 1.1 GitHub 계정 만들기

- https://github.com 에서 회원가입 (계정 생성)
- 본인 아이디 꼭 기억하고, 카톡으로 알려주세요.

### 1.2 GitHub 계정 연결 (Colab에서)

Colab은 매번 새 환경이라 Git 정보를 설정해야 합니다:

```bash
!git config --global user.name "홍길동"
!git config --global user.email "email@example.com"
import os
token = "여기에 본인 토큰"
repo_url = f"https://{token}@github.com/yujinoh0103/lung-cancer.git"
```

- 토큰은 GitHub > Settings > Developer Settings > Personal Access Tokens에서 발급받을 수 있습니다.
- 발급 받을 때 [Classic token] 누르시고, repo 체크박스 클릭해 전체 권한 부여해야 해요.

> 이메일은 GitHub 계정에 등록된 것과 같아야 합니다 (그래야 커밋 기록이 반영됨)

### 1.3 Google Drive에 저장소 클론하기 (추천)

저에게 id를 알려주시고 제가 공동작업자로 초대해야 실행 가능합니다.



## 2. 브랜치 전략

### 2.1 브랜치 구조

- `main`: 배포용 안정 버전 (**작업 금지**)
- `dev`: 모든 기능이 합쳐지는 개발용 브랜치
- `feature/기능이름`: 특정 기능 작업용 (예: `feature/login`)
- `본인 영어이름`: 각자 작업을 할 브랜치. 협업 편의를 위해 브랜치명을 이렇게 지정할게요 (예: `oyj`)

### 2.2 브랜치 생성

```bash
!git checkout -b oyj
```

> `oyj`는 본인의 영어 이니셜이나 이름으로 바꿔주세요.

## 3. 작업 & 커밋

작업을 완료한 후 매번 진행하셔야 하는 내용입니다.

- `add`: 스테이지에 자신이 작업한 내용을 올리는 것
- `commit`: 올라간 작업 내용을 메시지와 함께 자신의 컴퓨터에 기록해두는 것
- `push`: 커밋된 내용을 깃허브에 올리는 것

add를 하고 commit을 안 해두면 기록이 안되고 commit 후 push를 안하면 깃허브에 올라가지 않습니다. `.`은 폴더 내 전체 파일을 스테이지 위에 올린다는 의미입니다.

### 3.1 코드 작업 후 커밋

```bash
!git add .
!git commit -m "적고 싶은 메시지"
```

### 3.2 GitHub에 푸시

```
repo_url = f"https://{token}@github.com/yujinoh0103/lung-cancer.git"

!git push --set-upstream {repo_url} oyj
```

`push`의의 환경설정 같은 느낌으로, 런타임중 한번만 실행해도 괜찮습니다. **oyj를 자기 브랜치로 반드시 바꿔주세요** 에러납니다

```
!git push
```

위의 명령어가 실행된 이후부터 push 가능해집니다. 잘 안되면 `!git push {repo_url} oyj`로 시도해 보세요

## 💡 왜 복잡하게 이렇게 하느냐?

Colab과 연결할 때 단순히 `.ipynb`만 저장하지 않고 전체 프로젝트 폴더를 GitHub에 관리해 다른 사람들도 모두 실행할 수 있도록 합니다. vs코드 등에서 관리하는 게 일반적이라 코랩에서 설정하려니 복잡하긴 해요. 만약 이렇게까지 하고 싶지 않으시면, 저한테 colab 접근 권한 주시면 제 github 통해서 관리할 수 있도록 하겠습니다.
</br>
포트폴리오나 오픈소스를 위해 깃허브를 활용하려면:

- **코드 전체가 구조화되어 있어야 하고**
- **데이터나 민감한 정보는 `.gitignore`/`.env`로 분리해서 관리**해야 해요.

이런 구조가 바로 실무나 오픈소스에서 흔히 쓰는 방식입니다.

## 4. Pull Request (PR)

### 4.1 PR이란?

- GitHub에서 브랜치를 `dev`에 병합해달라고 요청하는 것
- 팀 리더 또는 관리자만 merge 가능

### 4.2 PR 작성 방법

- GitHub 저장소 > `Pull Requests` > `New Pull Request`
- base: `dev`, compare: 본인 브랜치 선택
- 작업 내용과 참고사항 작성

### 4.3 코드 리뷰 및 병합

- 리뷰 후 수정 요청이 있을 수 있어요
- 리뷰 통과되면 `dev` 브랜치에 merge합니다

---

## 5. 충돌 해결

- `git pull`로 최신 상태를 받아온 후 충돌 발생 시 수동으로 수정
- 수정 후 커밋하고 다시 push하면 됩니다

---

## 6. 협업 팁

- 커밋 메시지는 prefix 사용 권장: (`feat:`, `fix:`, `docs:` 등)
- `.gitignore` 파일을 꼭 활용해 불필요한 파일은 제외하기 (예: `__pycache__/`, `.ipynb_checkpoints/`)
